# Аудит «жёсткой петли»: где решала модель и где теперь решает код

Цель архитектуры: в точках принятия решения LLM нет вообще — там Jev (каталог
операторов + детерминированный поиск), Z3 (инварианты) или другая чистая логика.
Агент — технический исполнитель, который не может закрыть шаг или задачу словами.

Ниже — честная карта по коду: кто принимал решение **до** этого аудита, кто
принимает **после**, и что принципиально не гарантируется никаким шлюзом.

## 2. Где LLM остаётся — и почему это не точка решения

* `corpus::LlmExtract` — модель **извлекает** заметки из фрагмента. Но решение
  «заметка принята» принимает `ledger::verify_statement`: цитата должна
  буквально находиться в источнике по указанной позиции. Модель — датчик,
  судья — код.
* Встроенный агент (`agent/mod.rs`) использует модель для действий GUI. Его
  закрытие тоже идёт через `back_gate::seal_route` (с `EndoscopePolicy::Optional`,
  поведение не менялось).

## 3. Честные пределы (что код гарантировать не может)

1. **Предпосылки `have`.** Шлюз не может сам проверить «есть авторизованная
   сессия Instagram». Он может лишь не скрывать, что это допущение. Для
   частного использования правильный процесс: `have` передаёт оркестратор или
   человек, а не агент. Для массового — смотреть поле `assumptions` в отчёте.
2. **Смысл содержимого.** Свидетель доказывает, что файл/страница/экран
   существовали, были захвачены шлюзом и содержат фрагменты критерия. Он не
   доказывает, что агент их *понял*. Поэтому критерии `done_when` должны быть
   проверяемыми фразами в кавычках, а не «агент убедился».
3. **Агент с собственными инструментами** (Cursor, Claude Desktop с другими
   MCP-серверами) может делать что угодно *мимо* шлюза. Шлюз это не запретит.
   Но такие действия не порождают свидетелей, а без свидетелей шаг не
   закрывается, печать не ставится и `jev_report` говорит «НЕ ПОДТВЕРЖДЕНО».
   Невидимая работа = несделанная работа. Это и есть «технически не обойти»:
   обойти можно исполнение, но нельзя обойти подтверждение.
4. **Подмена наблюдаемого объекта.** Агент может создать файл с нужными
   словами и показать его шлюзу. Защита — в каталоге операторов: критерии
   должны указывать на объекты, которые агент не производит сам (URL
   продакшена, вывод `git status`, экран приложения), и на `command`/`url`/`screen`
   вместо `file` там, где это возможно (профиль `custom` + `PCAGENT_GATE_PROBES`
   позволяет запретить `file` целиком).
5. **Эндоскоп** остаётся обязательным для MCP-шлюза: без него печати нет.

## 4. Профили

| Переменная | strict (умолчание) | custom |
|------------|--------------------|--------|
| `PCAGENT_GATE_PROFILE` | не задана / любое значение кроме `custom` | `custom` |
| `PCAGENT_GATE_MIN_BYTES` | 32 | любое ≥ 1 (ноль не принимается) |
| `PCAGENT_GATE_PROBES` | `file,url,command,screen` | подмножество через запятую |

Что профиль **не может**: разрешить текстовое доказательство, выключить
привязку свидетеля к шагу, снять якорь с печати, обойти эндоскоп.
