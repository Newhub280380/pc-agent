# PC Agent — автономный цифровой сотрудник для Windows

Нативное десктоп-приложение: один `.exe`, без Python, без рантаймов, без установщика.
Агент видит экран, работает вашей мышью и клавиатурой в вашем браузере, помнит,
что делал вчера, учится на своих ошибках и умеет управлять Android-телефоном по ADB.

```
Rust (ядро)        цикл Восприятие → Мышление → Действие, планировщик, память, рефлексия, GUI
C++ (руки и глаза) WinAPI: захват экрана, UI Automation, OCR, поиск по картинке, SendInput, буфер обмена
Go  (сеть)         LLM Router: 8 провайдеров, retry / fallback / circuit breaker, автообновление
```

Go-роутер вшивается внутрь `.exe` ядра (`include_bytes!`) и поднимается на
`127.0.0.1` как дочерний процесс. Наружу приложение слушает **ничего**.

## Быстрый старт (готовый .exe)

1. Двойной клик по `pcagent.exe`.
2. Один раз согласиться с доступом (окно согласия) — создастся ярлык на рабочем столе.
3. Рядом появится `.env`. Вписать ключ **любого одного** провайдера (или нескольких — будет резерв).
4. Перезапустить, написать задачу, нажать **Старт**.

Файлы приложения: `%LOCALAPPDATA%\PCAgent\` (`.env`, `memory.db`, `consent.json`, логи).
Конфиг ищется в четырёх местах, первый найденный побеждает: `%PCAGENT_HOME%`,
папка рядом с `pcagent.exe`, текущая папка, `%LOCALAPPDATA%\PCAgent`.
В логе на старте видно, откуда прочитано:

```text
Loading LLM config from: C:\agent\config.json | .env: C:\agent\.env | искали в: ...
Found key: true (provider: youtoria, source: config.json)
Using base_url: https://api.youtoria.ai/v1 (model: gpt-4o)
```

## Сборка .exe под Windows

Ставится один раз:

| Что | Зачем |
|---|---|
| [Rust](https://rustup.rs) (toolchain `stable-x86_64-pc-windows-msvc`) | ядро и GUI |
| [Go 1.21+](https://go.dev/dl/) | LLM-роутер |
| Visual Studio Build Tools 2022 + Windows 10/11 SDK (workload «Разработка на C++») | C++/WinRT OCR, UI Automation, WIC |

Затем:

```powershell
git clone <repo> pc-agent
cd pc-agent
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Результат: `dist\pcagent.exe` — один файл, внутри уже лежит роутер.

Порядок в скрипте не случайный: Go собирается первым, иначе `build.rs` вошьёт
в ядро пустой роутер и агент при старте попросит собрать Go-часть.

Ручной эквивалент:

```powershell
cd router; $env:CGO_ENABLED="0"; $env:GOOS="windows"; $env:GOARCH="amd64"
go build -ldflags "-s -w" -o pcagent-router.exe .
cd ..\core; cargo build --release
```

Цель сборки — только `x86_64-pc-windows-msvc`. Вариант
`--target x86_64-pc-windows-gnu` (mingw) не поддерживается и падает осознанной
ошибкой из `build.rs`: C++/WinRT-интерфейсы OCR и UI Automation есть только в
MSVC-заголовках, под mingw их нет.

### Проверка сборки без GUI

```powershell
dist\pcagent.exe --selfcheck --report selfcheck.txt   # пути, .env, роутер, экран, память
dist\pcagent.exe --shot screen.png                    # снимок экрана глазами агента
```

`--selfcheck` возвращает ненулевой код, если хоть одна проверка провалилась —
этим же пользуется windows-джоб CI и складывает отчёт со скриншотом в артефакт
`pcagent-windows-smoke`.

### Сборка ядра на Linux/macOS

`cargo check` / `cargo test` работают везде: платформенный слой подменяется
заглушкой (`src/platform/stub.rs`), C++ не компилируется. Это для CI и разработки
логики — реальные действия существуют только под Windows.

## LLM-провайдеры

Приоритет источников: **`config.json` → переменные окружения → `.env`**.
Любой OpenAI-совместимый сервис (Youtoria и т. п.) подключается тремя полями
в `config.json` рядом с `pcagent.exe` — см. `config.example.json`:

```json
{
  "llm_provider": "youtoria",
  "base_url": "https://api.youtoria.ai/v1",
  "api_key": "sk-xxx",
  "model": "gpt-4o"
}
```

`base_url` и `model` берутся из кабинета провайдера: если хост не отвечает,
роутер сразу пишет `Сервер LLM недоступен`, а не «не вышло за 3 попытки».

Те же значения можно задать через `.env`/окружение как `LLM_PROVIDER`,
`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Привязки к одному вендору нет,
поддержаны также:

| Провайдер | Ключ | Vision |
|---|---|---|
| OpenAI | `OPENAI_API_KEY` | да |
| Anthropic | `ANTHROPIC_API_KEY` | да |
| Google Gemini | `GEMINI_API_KEY` | да |
| DeepSeek | `DEEPSEEK_API_KEY` | нет |
| Grok / xAI | `XAI_API_KEY` | да |
| Qwen | `QWEN_API_KEY` | да |
| OpenRouter (любые OpenSource-модели) | `OPENROUTER_API_KEY` | зависит от модели |
| Youtoria (OpenAI-совместимый) | `YOUTORIA_API_KEY` + `YOUTORIA_BASE_URL` | да |
| Локальная модель (LM Studio / Ollama / llama.cpp) | `LOCAL_BASE_URL` | зависит от модели |

Порядок задаётся `LLM_PRIORITY` (провайдер из `config.json`/`LLM_*` всегда первый). Роутер сам:
- перед попытками проверяет, живой ли хост, и на мёртвом отвечает `Сервер LLM недоступен` без ретраев;
- ретраит с экспоненциальной паузой на 429/5xx;
- уходит на следующего провайдера при отказе;
- размыкает цепь (circuit breaker) на 60 с после серии ошибок, чтобы не жечь лимиты;
- для шагов со скриншотом пропускает провайдеров без vision.

API роутера (только localhost, заголовок `X-Agent-Token`):
`GET /health`, `GET /v1/providers`, `POST /v1/complete`.

## Как агент думает

```
задача → планировщик строит ГРАФ задач (DAG с зависимостями и откатом) → цикл ReAct:
      восприятие (UI-дерево + OCR + скриншот) → память нужной полки + последние 10 шагов
      → Thought (цель, риски, уверенность) → grounding-проверка утверждений
      → уверенность < 0.8? уточняющий вопрос человеку, без действия
      → Action (ровно одно) → повторное наблюдение → Observation → self-verify
      → узел закрывается только независимой проверкой критерия по экрану
      → ошибка? разбор причины → урок в БД → лимит попыток → откат → перепланирование
```

«Зарегистрируйся на сайте» агент сам раскладывает на «найти форму → заполнить →
пройти проверку → подтвердить почту», а «поставь Fable 5» — на «проверить диск →
скачать → установить → запустить». Граф строится LLM, валидируется в коде
(циклы, дубли, висячие зависимости, лимит узлов) и переписывается на ходу.

### Граф задач и откат

Узел = наблюдаемый результат + `done_when` (как понять по экрану) + `deps` +
`rollback`. Независимые узлы не выстраиваются в ложную цепочку; провал узла
помечает его потомков пропущенными и запускает откат выполненного в обратном
порядке (`удалить скачанный файл`, `закрыть окно`), и только потом
перепланирование остатка. Файл: `core/src/agent/graph.rs`.

### Три механизма против галлюцинаций

1. **Grounding** (`core/src/agent/grounding.rs`): пути, ссылки и имена кнопок из
   ответа модели сверяются с наблюдением (UI-дерево, OCR, вывод инструмента,
   текст задачи, реальная ФС). Выдумка отклоняется ДО действия, а модель получает
   обратную связь «этого на экране нет».
2. **Self-verify** (`core/src/agent/verify.rs`): Do → Verify → Report. После
   действия экран читается заново тем же инструментом и сверяется с ожиданием
   (экран изменился / текст виден / нужное окно в фокусе). `Unknown` успехом не
   считается. `subtask_done` закрывает узел только после независимой проверки
   критерия, где проверяющий обязан привести дословную цитату с экрана.
3. **Uncertainty** (`core/src/agent/react.rs`): уверенность ниже `0.8` (и `NaN`) —
   вместо действия уточняющий вопрос человеку.

Отчёт «всё готово» без ни одного подтверждённого шага отклоняется.

### Песочница и таймауты

Любой внешний процесс (`launch_app`, все вызовы `adb`) идёт через
`core/src/sandbox.rs`: чёрный список системных утилит (`format`, `diskpart`,
`vssadmin`, `bcdedit`, `wmic`, `shutdown`, …), отказ от скрытых и base64-нагрузок
PowerShell, жёсткий таймаут с убийством процесса и лимит на объём вывода.
Сетевые вызовы и планирование обёрнуты в retry с экспоненциальной задержкой
(`core/src/retry.rs`).

### Память по полкам

Требование «не читать весь массив» решено двумя уровнями:

1. **Полка** выбирается детерминированно по экрану: `web:facebook.com`,
   `app:com.google.android.youtube`. Без запроса к LLM.
2. **Внутри полки** — SQLite FTS5/BM25 + важность + свежесть + частота
   использования. В контекст уезжает 5–10 записей, независимо от того, 1 000
   их в базе или 100 000. Плюс однострочный `digest` полки — «что я вообще знаю
   про это место».

### Самообучение

После каждой ошибки агент просит модель разобрать причину, сохраняет урок с
подписью (`контекст + действие + текст ошибки`) и подмешивает его в промпт при
следующем визите. Если следующий шаг после урока прошёл — уроку засчитывается
успех, и он поднимается в выдаче.

## Действия

Закрытый список (модель не может выполнить произвольный код):

`click_element`, `click_xy`, `type_text`, `key_combo`, `scroll`, `drag`,
`open_url`, `launch_app`, `focus_window`, `wait`, `remember`, `ask_user`,
`adb_tap`, `adb_swipe`, `adb_text`, `adb_key`, `adb_open_app`, `adb_shell`,
`subtask_done`, `finish`, `need_tool`.

`need_tool` — это то самое «не отказываться»: если не хватает доступа или
программы, агент называет, что именно поставить и как.

## Android

```
ADB_PATH=C:\platform-tools\adb.exe   # если не в PATH
ADB_WIFI=192.168.1.50:5555           # по Wi-Fi (первый раз всё равно кабель)
ADB_SERIAL=                          # если телефонов несколько
```

Телефон «виден» через `uiautomator dump` — XML со всеми элементами и их
координатами, это точнее скриншота и дешевле по токенам. Скриншот уходит в
модель только когда XML пустой (игры, Flutter, Canvas).

Ввод не-ASCII текста Android умеет только через IME: поставьте
[ADBKeyboard](https://github.com/senzhk/ADBKeyBoard) — иначе агент прямо скажет,
что кириллицу набрать не может.

## RADAR — поиск лидов по нише и ГЕО

Пакетный режим без GUI: ищет организации в радиусе, фильтрует по нише, считает
Intent Scoring и складывает в SQLite + JSON.

```
pcagent.exe --radar radar.json --out leads.json
```

Ниша, ключевые слова, маркеры сделки и ГЕО задаются файлом (шаблон —
`radar.example.json`), пересборка не нужна. База лидов — `radar.db` рядом с
памятью агента, дедуп по нормализованному телефону (`8 707…`/`+7 707…` → один
лид), при повторном прогоне score и intent обновляются.

Источники: **overpass** (OpenStreetMap, без ключа) и **two_gis** (нужен
`TWOGIS_API_KEY` в `.env`/`config.json`); **fixture** проигрывает сохранённый
ответ офлайн. Падение одного источника не роняет прогон — ошибка попадает в
отчёт, остальные источники работают.

Intent: `HOT` — маркеров («цена», «заказ», «доставка», «каспи», «запись») не
меньше `hot_threshold` и есть канал связи, `WARM` — канал есть, маркеров мало,
`COLD` — писать некуда. В `matched` видно, что именно сработало.

Границы модуля: собираются только контакты, опубликованные самим бизнесом как
канал входящих обращений. Личные номера из переписок и комментариев не
парсятся, проверок номера в банковских сервисах и мессенджерах нет — это
обработка чужих персональных данных без согласия (ст. 8 закона РК «О
персональных данных») и быстрый путь к блокировке номера.

## Безопасность и «режим Человек»

- Все действия идут через настоящий ввод (`SendInput`) в вашем браузере с вашим
  профилем и куками — никаких API-запросов «от бота» и никаких headless-браузеров.
- Перед вводом агент ждёт, пока вы не трогаете мышь: он не дерётся с вами за курсор.
- 2FA/SMS: агент показывает окно «введи код» и ждёт. Секретные ответы не попадают
  ни в лог, ни в память, ни в историю, уходящую в LLM.
- Необратимые действия (удаление, оплата, отправка) требуют подтверждения.
- CAPTCHA агент не обходит — он передаёт её вам.
- Ключи API не логируются, роутер слушает только `127.0.0.1` и требует токен.
- Обновления (если включены) проверяются по SHA-256 и ограничены по размеру.

## Известные ограничения

- C++-слой и GUI собираются и работают **только под Windows**; на Linux ядро
  компилируется в stub-режиме.
- OCR — встроенный `Windows.Media.Ocr` (без внешних моделей). Он слабее
  Tesseract/PaddleOCR на мелком тексте; замена — в roadmap v2.
- Поиск по картинке — собственный template matching, без ONNX-детектора.
